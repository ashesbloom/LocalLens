# Skip duplicates when sorting: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** an opt-in "Skip duplicates" switch for Standard and Hybrid sorts. It leaves out photos already in the destination and extra copies inside the source. After a Move, it asks what to do with the skipped photos.

**Architecture:** a pre-sort step in `run_organization_task` (backend/main.py) hashes the source and destination with the existing fingerprint cache and grouping. It then hands the sort only the kept files, through the existing `specific_files` field. `organizer_logic.py` is unchanged. The frontend adds a switch and a skipped variant of `MoveCompleteModal`. "Review" reuses the sub-project 2 Compare flow.

**Tech Stack:** FastAPI, numpy pHash (existing), React (Vite) and Tauri.

**Spec:** `docs/superpowers/specs/2026-10-12-skip-duplicates-design.md`

## Global Constraints
- The switch is off by default, not persisted, and sent only when on. With it off, there's no hashing and no behaviour change.
- Matching is fixed at `max_distance = 3` (Near-identical).
- Skipped photos are never written, moved or deleted by the sort itself.
- `organizer_logic.py` stays untouched.
- The CHANGELOG entry is concise and public-facing (one line).

## Review Focus
- Source inside the destination: a source file must not match itself (exclude the source subtree from the destination walk). Tested in Task 1.
- A hard link between source and destination: still counts as "already there" (separate inode sets). Tested in Task 1.
- Every photo skipped: the job completes with a clear message and `process_photos` doesn't run. Tested in Task 2.
- Unreadable source photo: sorted as normal, never skipped. Tested in Task 1.
- Abort during the duplicate check: status "aborted", the destination is untouched. Tested in Task 2.

- `_hash_files(files, cancel_event, progress) -> (file_hashes: list[(path, uint64)], file_info: {path: {width,height,bytes,mtime}}, skipped: int)`. Uses the cache, raises `OperationAbortedError` when `cancel_event` is set, and calls `progress(idx, total)` every ~1%.
